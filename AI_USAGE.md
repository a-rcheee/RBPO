# Использование генеративного ИИ

- Участник: M1
- Задача: выделить ключевые защитные свойства системы и составить критерии приёмки для S02
- Использование ИИ: предложены варианты формулировок
- Проверка человеком: отсеяны избыточные технические детали, вручную скорректированы статусы заявок
- Связанный результат: таблица в `SECURITY_REQUIREMENTS.md`

## Сопоставление требований со стандартом

- Участник: M1
- Задача: подобрать подходящую категорию OWASP ASVS для проверки полноты требований
- Использование ИИ: выполнен поиск релевантных пунктов стандарта под контекст разделения обязанностей
- В проект вошло: ссылка на пункт ASVS v5.0.0-4.1.5 для требования SR-01
- Проверка человеком: проверена применимость пункта к бизнес-логике согласования в кампусе
- Связанный результат: раздел «Соответствие стандарту OWASP ASVS» в `SECURITY_REQUIREMENTS.md`

## Построение модели угроз

- Участник: M2
- Задача: сформулировать конкретные сценарии угроз и связать их с требованиями безопасности для S03
- Использование ИИ: предложены черновые формулировки угроз по границам доверия и точкам входа API
- Проверка человеком: отобраны релевантные сценарии, уточнены приоритеты через последствия и реалистичность, проверены связи `T-* → SR-*`
- Связанный результат: модель угроз в `threat_model.md` (T-01…T-12, границы доверия, приоритетный набор)

## Разработка проектных решений безопасности

- Участник: M3
- Задача: предложить инженерные решения для приоритетного набора угроз к S04
- Использование ИИ: предложены варианты построения решений по авторизации, жизненному циклу заявки, аудиту и конкурентному доступу
- Проверка человеком: проверена применимость к архитектуре AccessFlow, уточнены будущие проверки и ограничения, сверены связи с T и SR
- Связанный результат: проектные решения в `design-decision.md` (D-01…D-05, покрытие приоритетного набора)

## Минимальная запускаемая техническая основа

- Участник: M2
- Задача: получить запускаемый каркас веб-API к EK1
- Использование ИИ: предложен черновой каркас на ASP.NET Core (модели, DbContext, эндпоинты создания и согласования заявки)
- Проверка человеком: код собран и запущен локально, проверены сценарии через Swagger, исправлены ошибки сборки и зависимостей
- Связанный результат: папка `AccessFlow/` в репозитории (веб-API, раздел 10 в `PROJECT.md`)
